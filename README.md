# 🎬 Personalized Movie Recommendation & User Preference Analytics Platform

A full-stack data science project combining **content-based filtering**,
**collaborative filtering (matrix factorization)**, a **hybrid recommender**,
**MongoDB Atlas** as the operational data store with full CRUD, and a
**Streamlit** dashboard for browsing, rating, and tracking movies.

Built on the [MovieLens ml-latest-small](https://grouplens.org/datasets/movielens/) dataset
(9,742 movies, 100,836 ratings, 610 users).

---

## Architecture

```
MovieLens CSVs
      │
      ▼
Data Cleaning & Feature Engineering (src/data_preprocessing.py)
      │
      ├──► Content-Based Model (TF-IDF + cosine similarity)
      ├──► Collaborative Filtering (SVD matrix factorization)
      └──► Hybrid Recommender (weighted blend, cold-start fallback)
      │
      ▼
MongoDB Atlas (users, movies, ratings, watchlist, interactions)
      │
      ▼
Streamlit App (login, browse, rate, watchlist, recommendations, analytics)
```

## Results (measured, not estimated)

Evaluated with an 80/20 train/test split (`src/evaluation.py`):

| Metric | Value |
|---|---|
| RMSE (rating prediction) | **0.930** |
| MAE (rating prediction) | **0.719** |
| Precision@10 | **0.124** |
| Recall@10 | **0.118** |
| Hit Rate@10 | **0.608** |

Re-run `python src/evaluation.py` any time — these numbers regenerate from
a fresh random split, so expect small variation run to run.

EDA figures (generated by `notebooks/eda.py`) live in `notebooks/figures/`:
rating distribution, ratings-per-user, ratings-per-movie, genre popularity,
and average rating by genre.

## Setup

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Set up MongoDB Atlas

1. Create a free cluster at [mongodb.com/cloud/atlas](https://www.mongodb.com/cloud/atlas/register).
2. In **Database Access**, create a user with a password.
3. In **Network Access**, allow your current IP (or `0.0.0.0/0` for quick local testing).
4. Click **Connect → Drivers**, copy the connection string.
5. Copy `.env.example` to `.env` and paste your connection string into `MONGO_URI`.

```bash
cp .env.example .env
# edit .env with your MONGO_URI
```

### 3. Seed the database

```bash
python scripts/load_data_to_mongo.py
```

This upserts all 9,742 movies (with cleaned titles, genres, and rating
stats) into the `movies` collection and creates the indexes the app needs.

### 4. Train the recommendation models

```bash
python scripts/train_models.py
```

Saves `models/content_model.pkl` and `models/collaborative_model.pkl`.

### 5. Run the app

```bash
streamlit run app/app.py
```

Register an account, rate a handful of movies, and watch the
recommendations and analytics update.

## How the hybrid recommender works

- **New user / fewer than 5 ratings** → content-based only (or pure
  popularity if they've rated nothing yet). Collaborative filtering has no
  signal for a user it's never seen, so it's skipped rather than guessed at.
- **Established user (5+ ratings)** → both models score every candidate
  movie, each score is min-max normalized to [0, 1], then blended:

  ```
  final_score = 0.4 × content_score + 0.6 × collaborative_score
  ```

  These weights (`content_weight`, `collaborative_weight` in
  `src/recommender.py`) are a reasonable starting point, not a tuned
  optimum — a natural next step is grid-searching them against
  Precision@K on a validation split.

## Honest limitations / next steps

- **SVD is trained once, offline.** In production you'd retrain on a
  schedule (or use incremental/online methods) rather than reloading a
  static `.pkl` on every app restart.
- **ml-latest-small is small.** Collaborative filtering quality would
  improve noticeably on ml-25m, at the cost of the dense-matrix approach
  here needing to switch to a properly sparse/ALS-based method.
- **Password hashing is SHA-256 + a static salt** — fine for a portfolio
  demo, not production-grade. Swap in `bcrypt`/`argon2` (via `passlib`)
  for anything real.
- **No pagination** on Browse — fine at ~9.7k movies, would need it at
  scale.
